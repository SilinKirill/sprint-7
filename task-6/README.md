# Задание 6 — Ежедневное обновление индекса

## Краткое описание

Источник данных — локальная папка `task-6/incoming/`: копия базы задания 2
и добавляемые Markdown/TXT-документы. При запуске `update_index.py` сканирует
папку и вложенные каталоги, сравнивает SHA-256 файлов и обрабатывает добавления,
изменения и удаления.

Используется разбиение задания 3 на чанки по 100–300 слов и та же версия
Qwen3-Embedding-0.6B, размерность — 1024. Короткий документ остаётся одним чанком.
Эмбеддинги создаются только для новых текстов; подходящие векторы используются
повторно, при первой сборке — из индекса задания 3. Ollama для индексации не нужна.

Результат — `index/snapshot.zip`, содержащий `faiss.index`, `chunks.jsonl`
и `report.json`. Новый снимок проверяется перед атомарной заменой рабочего.
Ошибка до замены не повреждает прежний индекс. Блокировка запрещает параллельное
обновление. Бот перечитывает изменённый снимок между вопросами.

Архитектура: [диаграмма PlantUML](architecture.puml).

## Запуск

Команды PowerShell выполняются из корня `sprint-7`. Требуются окружение Python,
база задания 2, индекс задания 3 и скачанная модель эмбеддингов.

### Подготовка и обновление

```powershell
& .\.venv\Scripts\python.exe -m pip install -r .\task-6\requirements.txt
if (-not (Test-Path .\task-6\.env)) { Copy-Item .\task-6\.env.example .\task-6\.env }
& .\.venv\Scripts\python.exe .\task-6\init_source.py
```

В `.env` задаются устройство энкодера и настройки Ollama/Telegram.
`.env` и рабочая копия `incoming/` исключены из Git.
`init_source.py` однократно копирует документы из `task-2/knowledge_base/`;
существующую папку не перезаписывает.

```powershell
& .\.venv\Scripts\python.exe .\task-6\update_index.py
```

Повторный запуск без изменений возвращает `unchanged` и не загружает энкодер.
Для обычного обновления удалять рабочий индекс не требуется.

### Воспроизведение эксперимента

Telegram-бот запускается при работающей Ollama. Один токен используется
только одним процессом бота:

```powershell
& .\.venv\Scripts\python.exe .\task-6\bot.py
```

В другом окне PowerShell:

```powershell
& .\.venv\Scripts\python.exe .\task-6\demo_document.py add
& .\.venv\Scripts\python.exe .\task-6\update_index.py
```

Скрипт создаёт `update_demo.md` и печатает вопрос в строке `Question:`.
Ответ на этот вопрос в Telegram после добавления — **17 дней**.

```powershell
& .\.venv\Scripts\python.exe .\task-6\demo_document.py change
& .\.venv\Scripts\python.exe .\task-6\update_index.py
```

Ответ на тот же вопрос после изменения — **29 дней**.

```powershell
& .\.venv\Scripts\python.exe .\task-6\demo_document.py remove
& .\.venv\Scripts\python.exe .\task-6\update_index.py
```

После удаления ожидается **«не знаю»**. Бот между этапами не перезапускается.
`remove` удаляет только демонстрационный документ и его служебное состояние.

Для консольной проверки вместо Telegram подставьте напечатанный вопрос
вместо `QUESTION`:

```powershell
& .\.venv\Scripts\python.exe .\task-6\query.py --query "QUESTION" --sources-only
& .\.venv\Scripts\python.exe .\task-6\query.py --query "QUESTION"
```

Первая команда показывает найденные источники без генерации; вторая — ответ RAG.

### Ежедневное расписание

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File .\task-6\schedule.ps1
```

Создаётся задача `Sprint7-Task6-DailyIndex`: ежедневно в **18:00 по локальному
времени**, от текущего вошедшего пользователя. Компьютер должен быть включён.
Пропущенный запуск выполняется при возможности; после ошибки предусмотрены
две попытки с интервалом пять минут. Лимит — 30 минут, параллельные запуски запрещены.
Другое время задаётся параметром `-At 'HH:mm'`.

Проверка запуска через планировщик:

```powershell
Start-ScheduledTask -TaskName 'Sprint7-Task6-DailyIndex'
Get-ScheduledTaskInfo -TaskName 'Sprint7-Task6-DailyIndex'
Get-Content .\task-6\logs\updates.jsonl -Tail 2
```

Успех подтверждают завершённая новая запись журнала и `LastTaskResult=0`
для соответствующего запуска. Удаление расписания:

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File .\task-6\schedule.ps1 -Remove
```

### Журнал и ошибки

`logs/updates.jsonl` хранит начало и окончание запуска в UTC, статус,
число добавленных/изменённых/удалённых файлов, новых чанков, новых эмбеддингов,
переиспользованных векторов, размер индекса, длительность и ошибки.
При перехваченной ошибке записывается причина и возвращается ненулевой код
завершения; неопределённый размер индекса обозначается `null`.
При аварийном завершении оставшийся `index/.update.lock` удаляется вручную
только после проверки, что указанный в нём процесс больше не работает.
Принудительное завершение процесса ОС может не дать записать финальный лог.

## Результат

- Исходные **30 документов, 44 чанка** перенесены с повторным использованием
  всех 44 векторов, без генерации новых эмбеддингов.
- Добавление документа увеличило индекс до **45 векторов**; создан один эмбеддинг.
- Изменение документа пересчитало один эмбеддинг, остальные 44 использованы повторно.
- После удаления демонстрационного документа индекс вернулся к **44 векторам**.
- В Telegram без перезапуска подтверждены ответы **17 → 29 дней → «не знаю»**:
  [скриншот](telegram_add_update_delete.png).
- Планировщик проверен ручным запуском и автоматическим запуском
  **12.09.2026 в 02:10 по Москве** (`2026-09-11T23:10:01 UTC`).
  Автоматический запуск: `unchanged`, 44 вектора, 0 новых эмбеддингов,
  0 ошибок, **0,008 секунды**.
