# Задание 1. Исследование моделей и инфраструктуры

Бот создаётся для сотрудников QuantumForge Software, чтобы сократить время поиска по внутренним документам и количество повторных вопросов коллегам. Интерфейс — Telegram.

## 1. Сравнение LLM

Для сравнения выбраны локальная Qwen3-8B и две облачные модели: GPT-4.1 mini и YandexGPT Lite. Облачные варианты рассматриваются как недорогие модели для ответов по найденным документам.

| Критерий                           | Qwen3-8B                                                                                       | GPT-4.1 mini                                                                                | YandexGPT Lite                                                                                 |
|------------------------------------|------------------------------------------------------------------------------------------------|---------------------------------------------------------------------------------------------|------------------------------------------------------------------------------------------------|
| Качество ответов                   | Подходит для ответов по документам. Сжатие модели для экономии памяти может влиять на точность | Подходит для технических вопросов и формирования ответа по нескольким фрагментам            | Подходит для коротких ответов по найденному тексту; для сложных вопросов можно рассмотреть Pro |
| Скорость работы                    | На GPU подходит для интерактивных ответов; на CPU генерация медленнее                          | Ориентирована на быстрые ответы без длительного рассуждения; вычисления выполняет провайдер | Облегчённая модель для быстрого выполнения простых запросов; вычисления выполняет провайдер    |
| Стоимость владения и использования | Нет оплаты токенов. Расходы: оборудование, электричество и обслуживание модели                 | Сервер приложения и оплата API: $0,40 за 1 млн входных и $1,60 за 1 млн выходных токенов    | Сервер приложения и оплата API: около $1,64 за 1 млн входных или выходных токенов              |
| Удобство и простота развёртывания  | Нужно скачать модель, настроить запуск и выделить память                                       | Достаточно подключить API; модель обслуживает провайдер                                     | Достаточно подключить API; модель обслуживает провайдер                                        |

**Выбор — локальная Qwen3-8B:** нет платы за API, документы обрабатываются внутри компании. Компромисс — необходимость самостоятельно запускать и обслуживать модель.

## 2. Сравнение моделей эмбеддингов

| Критерий                           | Локальная Qwen3-Embedding-0.6B через Sentence-Transformers                                               | OpenAI text-embedding-3-small                                                                                 |
|------------------------------------|----------------------------------------------------------------------------------------------------------|---------------------------------------------------------------------------------------------------------------|
| Скорость создания индекса          | Работает на CPU или GPU; пакетная обработка на GPU ускоряет индексацию                                   | Пакетная обработка на стороне провайдера; собственный GPU не нужен                                            |
| Качество поиска                    | Предназначена для многоязычного поиска по текстам и коду; поддерживает инструкции для поисковых запросов | Поддерживает многоязычный поиск по смыслу, в том числе когда вопрос и документ сформулированы разными словами |
| Стоимость владения и использования | Нет платы за токены; нужны ресурсы компьютера и сопровождение модели                                     | $0,02 за 1 млн токенов документов и вопросов; локально модель запускать не нужно                              |

**Выбор — Qwen3-Embedding-0.6B через Sentence-Transformers:** локальная многоязычная модель для поиска по документам, поддерживающая длинные фрагменты текста. Используется размер вектора 1 024. Документы и вопросы кодируются одной моделью.

## 3. Сравнение FAISS и ChromaDB

| Критерий              | FAISS                                                                                                  | ChromaDB                                                                                                                            |
|-----------------------|--------------------------------------------------------------------------------------------------------|-------------------------------------------------------------------------------------------------------------------------------------|
| Скорость поиска       | В выбранном простом индексе выполняется точный перебор; время растёт с числом векторов                 | Приближённый поиск может быть быстрее на большом индексе, но способен пропускать часть ближайших результатов                        |
| Скорость индексации   | Быстрое добавление готовых векторов: выбранный простой индекс не требует обучения или построения графа | Дополнительное время на построение поискового графа и сохранение документов с метаданными                                           |
| Внедрение и поддержка | Работает внутри приложения; сохранением индекса и текстов управляет приложение                         | Можно запустить локально; хранением документов и метаданных управляет сама Chroma                                                   |
| Удобство              | Прост для базового поиска; обновления и фильтрация требуют дополнительного кода                        | Встроенные методы изменения и удаления документов, поиска с условиями по метаданным                                                 |
| Стоимость владения    | Бесплатная библиотека; расходы на RAM, CPU, диск и поддержку кода                                      | Бесплатна при самостоятельном размещении; нужны RAM для графа и диск для данных, но меньше собственного кода управления документами |

**Выбор — FAISS:** подходит для первого внедрения без отдельного сервиса. Источник и позиция фрагмента сохраняются вместе с текстом в приложении. Ежедневное обновление поддерживается добавлением векторов или пересборкой индекса; Chroma удобнее при сложной фильтрации и большом числе изменений.

## 4. Рекомендуемая конфигурация сервера

Стартовая конфигурация для первого внедрения в компании:

| Ресурс | Конфигурация и назначение                                                   |
|--------|-----------------------------------------------------------------------------|
| CPU    | 8 vCPU — обработка документов, эмбеддинги и поиск                           |
| RAM    | 32 GiB — приложение, модели, индекс, тексты и пакетная обработка            |
| GPU    | Видеокарта с 16 GiB видеопамяти — запуск Qwen3-8B в 4-битном представлении  |
| Диск   | SSD 100 GiB — документы, модель, индекс и журналы; резервные копии отдельно |

Конфигурация рассчитана на одну активную генерацию с контекстом до 8 тысяч токенов. Эмбеддинги и поиск могут выполняться на CPU, оставляя видеопамять для LLM.

## Итоговые рекомендации

Во всех вариантах используются Telegram, Python/LangChain, Qwen3-Embedding-0.6B и FAISS.

| Вариант                    | Генерация ответа                      | Инфраструктура                                   | Преимущества и ограничения                                                                    |
|----------------------------|---------------------------------------|--------------------------------------------------|-----------------------------------------------------------------------------------------------|
| **1. Основной: локальный** | **Qwen3-8B в 4-битном представлении** | **8 vCPU, 32 GiB RAM, GPU с 16 GiB видеопамяти** | Нет оплаты API и внешней AI-обработки; требуется настройка и обслуживание модели              |
| 2. Облачный                | GPT-4.1 mini через API                | 8 vCPU, 32 GiB RAM, GPU необязателен             | Проще обслуживание, но есть оплата API и передача фрагментов провайдеру                       |
| 3. Альтернативный облачный | YandexGPT Lite через API              | Такая же, как в варианте 2                       | Другой провайдер; при приведённых тарифах API дороже. Ограничения передачи данных сохраняются |

При **5 000 вопросах в месяц**, по 4 000 входных и 500 выходных токенов, расходы API по приведённым ставкам составят около **$12 для GPT-4.1 mini** или **$37 для YandexGPT Lite**. Полная стоимость любого варианта также включает оборудование или аренду сервера, хранение и сопровождение.

**Выбран вариант 1: Telegram + Python/LangChain + Qwen3-8B + Qwen3-Embedding-0.6B + FAISS.** Локальные модели обеспечивают обработку документов без внешнего AI-сервиса и платы за токены. FAISS упрощает запуск и поддерживает обновление индекса. Основные затраты — оборудование и сопровождение. Для Telegram используются документы, разрешённые к передаче через этот канал.
