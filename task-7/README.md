# Задание 7 — Аналитика покрытия и качества базы знаний

## Краткое описание

Эксперимент сравнивает три независимых снимка индекса задания 6:
`baseline.zip` — исходная база, `gaps.zip` — база с искусственными пробелами,
`restored.zip` — восстановленное исходное содержание. Рабочий индекс задания 6
и исходные документы не изменяются, эмбеддинги заново не рассчитываются.

Из варианта `gaps` удалены три сущности: **Loraven-56, Dareoran-93 и Helaetor-20**.
Удаляются все чанки их основных документов и чанки других документов,
содержащие перечисленные в `gap_entities.json` псевдонимы. Получено
**44 → 38 → 44 вектора**, число документов — **30 → 27 → 30**.
Восстановленный снимок побайтово совпадает с исходным.

Золотой набор содержит **12 вопросов**: восемь по сохраняемым темам,
три по удаляемым сущностям и один по отсутствующей теме — текущей погоде.
Вопросы, эталоны, ключевые слова и подтверждающие цитаты зафиксированы до
оцениваемых прогонов. В `baseline` и `restored` ожидаются 11 ответов и один
отказ, в `gaps` — восемь ответов и четыре отказа.

Используются локальная Ollama с Qwen3-8B, Qwen3-Embedding-0.6B и FAISS.
Система наследует поиск и защиту заданий 4–6. Поиск выбирает 12 кандидатов,
затем до трёх чанков из разных документов. Примеры выбираются из текущего
снимка; источники эталонных ответов исключены из few-shot. `grounding7.py`
требует сопоставлять все условия вопроса с одной сущностью и ограничивает
число цитат и пунктов пояснения тремя.

Диаграмма последовательности: [sequence.puml](sequence.puml).
На схеме два этапа: обработка одного вопроса с логированием и анализ после
трёх прогонов. Показаны пустой контекст, ошибки поиска и генерации, проверка
цитат и ожидаемый отказ. Автооценка по эталону применяется только к тестовым вопросам.

## Запуск

Команды PowerShell выполняются из корня `sprint-7`. Требуются окружение Python,
артефакты заданий 3–6, скачанный энкодер и работающая Ollama с `qwen3:8b`.

### Настройки

```powershell
& .\.venv\Scripts\python.exe -m pip install -r .\task-7\requirements.txt
if (-not (Test-Path .\task-7\.env)) { Copy-Item .\task-7\.env.example .\task-7\.env }
```

В `task-7/.env` задаются устройство энкодера и настройки Ollama/Telegram.
Токен требуется только для Telegram. `.env`, вспомогательный каталог источников
и черновики эталонов исключены из Git; готовые вопросы и результаты включаются.

### Проверка сохранённых результатов

Для чтения и повторного формирования отчёта запускать модель не требуется:

```powershell
& .\.venv\Scripts\python.exe .\task-7\analyze.py
& .\.venv\Scripts\python.exe -m unittest discover -s .\task-7 -p 'test_*.py'
```

`analyze.py` проверяет завершённость и совместимость трёх прогонов: базовый
снимок, эталоны, сущности, модель, версию пайплайна и принадлежность оценок
к текущим `run_id`. Результаты — [REPORT.md](REPORT.md) и
[results/summary.json](results/summary.json).

### Воспроизведение трёх прогонов

Снимки и золотой набор уже подготовлены. При работающей Ollama остановите
другие процессы бота и выполните:

```powershell
& .\.venv\Scripts\python.exe .\task-7\evaluate.py --variant baseline
& .\.venv\Scripts\python.exe .\task-7\evaluate.py --variant gaps
& .\.venv\Scripts\python.exe .\task-7\evaluate.py --variant restored
```

Повторный прогон перезаписывает результат своего варианта и сбрасывает
смысловые оценки в `results/review_<variant>.json`. История `logs.jsonl`
сохраняется, прогоны различаются по `run_id`.

После нового прогона сравните каждый `reply` с `expected_answer`, цитатами
из `golden_questions.json` и исходным документом. В `review_*.json` замените
`null` на `true` или `false`, сохранив `run_id`. Совпадение оценивается по смыслу;
ожидаемый отказ тоже считается правильным результатом. Затем запустите
`analyze.py`. Не меняйте эталоны задним числом под ответы модели.

### Подготовка нового эксперимента

Эти команды предназначены для новой копии эксперимента без готовых снимков
и золотого набора; существующие подготовленные файлы скрипт не перезаписывает:

```powershell
& .\.venv\Scripts\python.exe .\task-7\prepare.py --stage init
```

Скрипт копирует `task-6/index/snapshot.zip` в baseline и создаёт каталог источников,
шаблоны `gap_entities.json` и `golden_questions.json`. Выберите 2–3 сущности,
укажите основные документы и все известные псевдонимы. Заполните 10–15 вопросов:
6–8 по известным темам и 3–5 по удалённым или отсутствующим. Эталоны должны
подтверждаться точными цитатами источников; для отсутствующей темы ожидается отказ.

После заполнения золотого набора:

```powershell
& .\.venv\Scripts\python.exe .\task-7\prepare.py --stage gaps
```

Создаются `gaps.zip`, `restored.zip` и `golden_questions.txt`. Подготовка
проверяет, что удаление не затронуло эталонные цитаты сохраняемых тем.
Список псевдонимов требует проверки: неизвестные варианты названий и безымянные
описания автоматически не гарантируется удалить. После изменения эталонов,
сущностей или пайплайна необходим новый полный цикл оценки.

### Telegram и обычные запросы

Дополнительная проверка всей цепочки через Telegram:

```dotenv
EVALUATION_VARIANT=gaps
```

Укажите вариант в `task-7/.env`, затем запустите:

```powershell
& .\.venv\Scripts\python.exe .\task-7\bot.py
```

Один Telegram-токен должен использоваться только одним работающим процессом
бота. Остановка — `Ctrl+C`. Для смены варианта перезапустите бота.

Проверенные вопросы на `gaps`:

- `Where did Selivek-75 live?` — ответ: Kelosil, планета Elanor, с источником.
- `What was Helaetor-20 specially programmed to do?` — отказ: тема удалена.

Консольный вариант без Telegram:

```powershell
& .\.venv\Scripts\python.exe .\task-7\query.py --variant gaps --query "Where did Selivek-75 live?"
```

`logging7.py` записывает каждый запрос, переданный в RAG: текст, время UTC,
наличие чанков, найденные и использованные источники, ответ, его длину,
статус, длительность, ошибку и `run_id`. Команды `/start`, `/id` и сообщения,
отклонённые до вызова RAG проверкой доступа или длины, в этот журнал не попадают.
Ошибки инициализации останавливают запуск и не считаются отказами базы знаний.

Для обычного запроса `success` означает наличие ответа с проверенными цитатами.
Для золотого вопроса дополнительно рассчитывается `auto_pass`: ожидаемый статус,
попадание источника и полнота по ключевым словам. Поэтому корректный отказ может
иметь `success=false`, но `auto_pass=true`. Автооценка не доказывает правильность
смысла. После дополнительных запросов повторный `analyze.py` обновляет отчёт.

## Результат

- Удалены **3 сущности и 6 чанков**; известные темы сохранены.
- `baseline`: **12/12** автоматических проверок, 11 ответов, один отказ.
- `gaps`: **12/12**, восемь ответов, четыре отказа; все три искусственных пробела обнаружены.
- `restored`: **12/12**, 11 ответов, один отказ; ответы по всем трём темам восстановлены.
- В текущих трёх прогонах технических ошибок нет. Во всех ответах, ожидаемых
  по золотому набору, найден и процитирован нужный источник.
- Смысловая проверка выполнена Codex по эталонам и исходным документам:
  **36/36** верных результатов, включая ожидаемые отказы. Автор проверки указан
  в `notes` файлов `review_*.json`.
- В Telegram на `gaps` подтверждены ответ по Selivek-75 и отказ по Helaetor-20;
  оба запроса записаны в журнал. После проверки бот остановлен.
- **18/18** тестов кода прошли.

Логи содержат историю предыдущих запусков. Отчёт использует текущие завершённые
прогоны из `results/*.json` и совместимые дополнительные запросы. Среди последних
есть короткое сообщение `в` и два проверочных вопроса Telegram. Отказ по удалённой
теме ожидаем; это не дополнительный дефект базы.

Выводы и рекомендации — в [REPORT.md](REPORT.md): использовать восстановленные
документы для трёх тем, сохранять отказ по внешней теме текущей погоды, повторять
фиксированный набор при обновлениях. По этому набору оснований переписывать
остальную базу не выявлено. Результат ограничен выполненными вопросами и не
доказывает полное покрытие всех возможных запросов или актуальность внешних данных.
