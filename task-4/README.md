# Задание 4 — RAG-бот

## Краткое описание

Бот принимает вопрос, ищет 12 ближайших чанков в индексе задания 3,
выбирает по лучшему чанку максимум из трёх разных документов
и формирует ответ с кратким обоснованием и источниками.
Язык базы, промпта, few-shot, контрольных вопросов и ответов — английский.

- **Поиск:** Qwen3-Embedding-0.6B, 1024 измерения, FAISS из `task-3/index/`.
  Используются код и версия энкодера из задания 3.
- **Генерация:** локальная [Qwen3-8B](https://ollama.com/library/qwen3:8b)
  в 4-битном представлении через Ollama, контекст 8192 токена.
- **Few-shot:** два примера из реальных чанков, выбранных вне пяти документов
  контрольных вопросов. В ответах примеров приведены точные выдержки из источника.
- **CoT:** инструкция дать 2–3 кратких шага обоснования по найденным фактам.
  Внутренний поток размышлений не выводится; показываются объяснение и источники.
- **Отказ:** «I don't know: the knowledge base does not contain enough information.», если в контексте нет ответа.
- **Интерфейс:** Telegram через polling; консольный запуск использует тот же модуль RAG.

Модель выбирает ID выдержек из текущих чанков; код подставляет их дословный
текст. Неизвестные ID отклоняются.
Это не заменяет проверку смысла ответа. Ошибки сервиса и некорректные
цитаты считаются ошибками, а не успешными отказами. Каждый вопрос независим.

## Запуск

PowerShell, из корня проекта `sprint-7`.

**1. Установить [Ollama для Windows](https://ollama.com/download/windows)
и открыть новое окно PowerShell.** Скачать модель (около 5,2 ГБ):

```powershell
ollama pull qwen3:8b
```

Ollama должна оставаться запущенной. Она использует NVIDIA GPU автоматически;
после первого запроса это можно проверить командой `ollama ps`.

**2. Установить зависимости и создать локальный файл настроек:**

```powershell
& .\.venv\Scripts\python.exe -m pip install -r .\task-4\requirements.txt
if (-not (Test-Path .\task-4\.env)) { Copy-Item .\task-4\.env.example .\task-4\.env }
```

Эмбеддинг-модель по умолчанию работает на CPU, оставляя видеопамять для LLM.
Для её запуска на GPU установите `EMBEDDING_DEVICE=cuda` в `.env`.
Модель эмбеддингов загружается из существующего кэша; при его отсутствии
временно установите `EMBEDDING_OFFLINE=false`.

Проверить доступность локальной LLM:

```powershell
& .\.venv\Scripts\python.exe .\task-4\rag.py --check
```

**3. Подготовить few-shot-примеры:**

```powershell
& .\.venv\Scripts\python.exe .\task-4\prepare_examples.py
```

Если `few_shot.json` уже есть, повторно запускать `prepare_examples.py` не нужно.
После первой подготовки проверьте две пары «вопрос — ответ» в этом файле.
Скрипт берёт текст из индекса локально, не обращаясь к LLM или внешнему API.
После изменения индекса примеры пересоздаются с `--overwrite`.

**4. Проверить один ответ:**

```powershell
& .\.venv\Scripts\python.exe .\task-4\rag.py --query "Which unit was afraid of flying and compensated by excelling at ground maintenance?"
```

**5. Подключить Telegram.** В [BotFather](https://t.me/BotFather)
выполните `/newbot`, выберите имя и username. Полученный токен запишите
в `TELEGRAM_BOT_TOKEN` файла `task-4/.env`. Файл исключён из Git.

```powershell
& .\.venv\Scripts\python.exe .\task-4\telegram_bot.py
```

Откройте своего бота, нажмите Start и задайте вопрос. Для работы бота
нужны запущенные Python и Ollama, а также интернет для Telegram.
Вопросы и ответы проходят через Telegram; поиск и генерация выполняются локально.
При пустом `ALLOWED_USER_IDS` бот доступен всем. Для ограничения доступа
получите свой ID командой `/id`, внесите его в эту настройку и перезапустите бота.

**6. Сохранить семь контрольных диалогов** (после остановки бота через Ctrl+C):

```powershell
& .\.venv\Scripts\python.exe .\task-4\run_dialogues.py
```

В `dialogues.json` сохранятся реальные вопросы, ответы, объяснения,
цитаты, найденные чанки и время. Проверьте пять ответов и два отказа.
Скрипт отдельно считает совпадение ожидаемых статусов и ссылок;
фактическую правильность ответов нужно проверить по текстам.
Повторный запуск обновляет файл результатов.

## Результат

Подготовлены:

- `rag.py` — загрузка индекса, поиск, обращение к LLM и проверка цитат; также CLI/REPL.
- `prompts.py` — system-промпт, few-shot и краткое обоснование по источникам.
- `telegram_bot.py` — Telegram-интерфейс.
- `prepare_examples.py` — подготовка примеров из индекса.
- `questions.json`, `run_dialogues.py` — пять запросов по базе и два с ожидаемым отказом.
- `.env.example`, `requirements.txt` — настройки и зависимости.
- `few_shot.json` — два примера из базы для промпта.
- `dialogues.json` — результаты контрольного прогона с ответами и источниками.
- [telegram_demo.png](telegram_demo.png) — демонстрация ответа с обоснованием
  и источником, а также отказа на вопрос вне базы.

Telegram-интерфейс проверен: бот отвечает по найденным фрагментам и возвращает
отказ при отсутствии сведений. Контрольный набор включает пять вопросов по базе
и два вопроса с ожидаемым отказом; результаты каждого случая записаны в `dialogues.json`.
Итог прогона: **7/7 ожидаемых статусов, 5/5 ожидаемых источников**.
Эти показатели подтверждают статусы и ссылки, но не заменяют проверку смысла ответов.
